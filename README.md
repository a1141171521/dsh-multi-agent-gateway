# dsh-multi-agent-gateway

**Free Token —— 把各平台的免费额度，装进 DSH 的模型选择器。**

一个插件管起所有「AI Agent 平台」的账号：统一账号管理、每日签到、额度/积分拉取、
多账号智能路由；把各平台的模型**按平台分组**上报到 DSH 对话框的**原生模型选择器**，
并在每个模型名后标注**积分消耗倍率**。七个平台的适配器**已全部实现**。

不是独立 Nginx，也不是外部代理进程 —— 请求全部在插件内部转发，账号凭证只存在本机。
（本地 OpenAI 兼容网关属于**后续计划**，见[路线图](#路线图)。）

## 理念：Free Token

各平台为了拉新，会持续放出免费额度：OpenCode 的匿名免费层、Qoder / WorkBuddy 的
每日签到积分、Trae 的赠送额度……这些「免费 token」分散在七个客户端里，每个都要单独
登录、单独签到、单独查余额，最后往往是**放着过期**。

这个插件的立场很简单：

- **免费额度不该被浪费，也不该被平台 UI 绑架** —— 账号收进来、模型接进 DSH、
  签到与额度查询自动跑；
- **默认不烧钱** —— 模型默认一个都不勾，勾选并保存后才出现在选择器里
  （见 [`docs/MODELS.md`](docs/MODELS.md) §6.5），避免「白嫖」变成「意外扣费」；
- **福利跟进是长期承诺** —— 哪个平台出了新的免费模型或签到活动，适配器就跟着更新。
  各平台接口并不公开，我们坚持逐个真机验证，而不是照抄文档。

> 一句话：**能白拿的 token，一个都别浪费；拿不到的时候，我们自己写适配器。**


## 界面：五页 + 浏览器登录

设置页现在是**独立一页**（设置 → Free Token），内部按「你此刻要回答的问题」分五页：

| 页 | 回答什么问题 |
|---|---|
| **总览** | 现在健康吗？刚才那条花了多少？ |
| **账号** | 这个平台有哪些账号 / 模型？ |
| **任务** | 签到和活动任务跑得怎么样？ |
| **日志** | 刚才那次为什么失败？ |
| **设置** | 那些不常动的东西（含版本更新） |

**添加账号不用手抄 token**：账号页点「打开登录页」→ 浏览器里完成平台登录 → 回来稍等
几秒（会自动轮询），或点「刷新登录状态」→ 插件自己去换 token 并建账号
（token 不经过浏览器，加密落盘）。

| 平台 | 登录形态 |
|---|---|
| OpenCode | 设备码（显示 user_code，前端自动轮询） |
| WorkBuddy / 国际版 | 外链（`auth/state` → 打开登录页 → `auth/token?state=`） |
| Qoder / Qoder CN | 设备码 + PKCE |

> 两种形态都会**自动轮询**（3～5 秒一次）：浏览器里授权完成后回来即可看到变绿；
> 「刷新登录状态」只是手动补充入口，不是必点步骤。

**模型表**按「免费 → 厂商 → 倍率」排序，**默认一个都不勾** —— 勾选并「保存并生效」
之后才进选择器；还没勾过时可以点「按推荐预选」（OpenCode 推免费，其余平台推全部）。
每行可单独改上下文长度、可单独「测一次」，状态列显示 可用 / 地区受限 / 不可用 / 未探测。
上游声明了思考档位的模型，选择器里还能选 `off / low / medium / high…`。

## 它解决什么

| 你现在的麻烦 | 这个插件怎么办 |
|---|---|
| 有五六个平台、十几个账号，每个平台一套登录/签到/查额度 | 一个配置页全管起来，按平台分组 |

## 支持情况

七个平台的适配器**全部实现**，没有一个是「占位骨架」：

| Agent | 签到 | 额度 | 模型目录 | 对话 | 备注 |
|---|---|---|---|---|---|
| **OpenCode** | 上游无 / 可配 | ✅ | ✅ | ✅ 流式 + 思维链 | 匿名免费层零凭证可用；签到接口可填 `checkInPath` |
| **Qoder** | ✅ | ✅ | ✅ | ✅ | 签到 `/sash/api/v1/me/campaigns`、额度 `/sash/api/v2/me/usage` |
| **Qoder CN** | ✅ | ✅ | ✅ | ✅ | 同上，独立产品线与账号体系 |
| **WorkBuddy** | ✅ | ✅ | ✅ | ✅ | 签到 + 余额 + 会话头校验 |
| **WorkBuddy 国际版** | 上游无 | ✅ | ✅ | ✅ | 上游确实没有签到接口，如实回报「不支持」 |
| **Trae** | ✅ | ✅ | ✅ | ✅ 流式 | 协议层已实现，**默认隐藏**（尚未真机验证），显式配置后可启用 |
| **商汤小浣熊** | ✅ 登录积分发放 | ✅ 积分 | ✅ | ✅ 流式 + 思维链 + 工具调用 | **零配置**：自动读客户端登录态；10 个模型，其中 3 个 ×0 免费。见 [`docs/RACCOON-API.md`](docs/RACCOON-API.md) |

> **关于签到与活动任务**：opencode.ai 官方 Console 没有签到接口，国内反代平台则常见
> 「签到 + 活动任务」形态。所以本插件把接口路径做成**可配置**的：填了
> `upstream.checkInPath` / `tasksPath` 就真去调；没填就明确回报「上游没有这个接口
> （这不是故障）」，**绝不伪造签到结果**。详见 [`docs/OPENCODE-API.md`](docs/OPENCODE-API.md)。

### 「免费模型不要 key」——对，插件做到了**一个字段都不用填**

**不登录、不填 API key、不填凭证** —— 账号卡片里只填一个标签就完事，
模型选择器里选 `OpenCode · xxx (免费)` 直接聊。

为什么以前会 403、现在能过：上游那句 `FreeTierError`（*"can only be used from
within OpenCode"*）是**营销话术**，它实际校验的是**请求形状**。消融实验实测出来的
**过门三件事**：

| 条件 | 去掉会怎样 |
|---|---|
| `stream: true` | **403** —— 免费层只接受流式 |
| 请求里有一个叫 `read` 的工具 | **403** |
| 规范的 `x-opencode-session`（`ses_…` 降序编码） | **403** |

其余（`Authorization`、`x-opencode-request`、`x-opencode-project`）**去掉照样过**。

插件在「账号没有 key」时自动补齐这三样（`upstream.freeTierMode: 'auto'` 默认值），
`stream: true` 本来就是它的固定行为，`read` 工具 DSH 本来就发 —— 所以是真的零配置。
机制细节、实测报文、消融表见 [`docs/OPENCODE-API.md`](docs/OPENCODE-API.md) §1.5–1.6。

**实测证据**（`npm run test:free`）：空凭证账号 → 200 → 正文「收到」+
`reasoning_content` + usage，**全程没有任何 key**。

**边界**：匿名通道**只对免费模型有效**；付费模型在它上面会直接
`401 Missing API key`。要用付费模型就走登录/API key。上游随时可能再改门禁 ——
被拒时错误信息会把那三件事列出来，不会让你瞎试。

**另外**：模型目录完全免凭证，所以模型选择器里的分组与倍率
**一个账号都不加也能显示**，只是发不出请求。

**Trae 为什么默认隐藏**：适配器本身是能跑的（协议层、签到、余额、流式对话都实现了），
但本机没有 Trae 账号、没有一次真上游验证 —— 露出来只会让你点到一个没验证过的东西。
真机验证通过后，把 `trae` 加进 `src/config.ts` 的 `DEFAULT_VISIBLE_AGENTS` 即可显示，
别处不用改。

**扩展方法**见 [`docs/EXTENDING.md`](docs/EXTENDING.md)：新增一个平台只需加一个适配器
文件 + 在 `adapters/index.ts` 加一行，核心调度一行都不用改。

## 路线图

| 方向 | 说明 | 状态 |
|---|---|---|
| **新平台 / 新福利跟进** | 哪个平台放出新的免费模型、签到活动或赠送额度，就补对应适配器；接口以真机验证为准 | 持续进行 |
| **本地 OpenAI 兼容网关** | 增加本地端点（`POST /v1/chat/completions`、`GET /v1/models`），让 Cursor / VS Code / 任意 OpenAI SDK 也能用上这些账号与免费模型；端口可配、默认只绑 `127.0.0.1` | 规划中，未发布 |
| 界面与可用性 | 五页设置界面 + 左侧导航入口，继续打磨 | 持续进行 |

> 现阶段它是 **DSH 插件**，不是独立服务：请求由宿主进程调进来、在进程内转发。
> 等网关功能落地后，才会额外暴露一个可被外部客户端直连的端点。

## 架构（分层模块化）

```
                        ┌──────────────────────── DSH ────────────────────────┐
   对话请求 ──▶ ctx.llm ──▶ src/llm/adapter.ts（每 Agent 一个 provider 路由）
                        │            │                                    │
                        │            ▼                                    │
   模型选择器 ◀───────────│  src/runtime.ts（总装：模型缓存 / 分组 / 倍率标签）   │
                        │            │                                    │
   客户端配置页 ◀─ src/remote.ts ─┼─▶ core/router.ts  多账号路由（换号/降权/恢复）│
                        │            ├─▶ core/scheduler.ts 定时任务管理器    │
                        │            ├─▶ core/tasks.ts  活动任务引擎         │
                        │            └─▶ core/accounts.ts 账号（AES-256-GCM）│
                        │                       │                          │
                        │                       ▼                          │
   工具 ◀────────────────┘            src/adapters/*.ts（每 Agent 一个适配器） │
                        └────────────────────────────────────────────────────┘
```

**新增 Agent 只需要在 `src/adapters/` 加一个文件 + 在 `adapters/index.ts` 加一行。**
核心调度（路由 / 定时 / 任务 / 网关 / UI）一行都不用改。

## 数据落在哪

默认 `<DSH_HOME>/multi-agent-gateway`（`DSH_HOME` 一般是 `~/.dsh`）：

| 文件 | 内容 | 丢了会怎样 |
|---|---|---|
| `.master-key` | AES-256-GCM 主密钥（0600） | **账号密文再也解不开**，要重录 |
| `accounts.enc.json` | 账号与凭证（整份加密） | 要重录账号 |
| `state.json` | 额度缓存、健康、模型缓存、任务游标（明文、无敏感信息） | 重算，无损失 |
| `task-log.jsonl` | 任务执行流水（可删） | 历史记录没了 |

**安全边界（说清楚，不吹）**：密文与密钥分文件，防的是「配置被云同步 / 被 grep 到明文
token / 备份泄露」。它**不是硬件密钥库** —— 能读该目录的本机进程同样能读密钥。

## 开发

```powershell
node scripts/build.mjs      # TypeScript → lib/（零依赖，用 Node 自带的类型擦除）
npm test                    # 宿主测试 678 + 客户端契约 85 + 冒烟
node test/live-opencode.mjs # 真机管线：打真实 OpenCode 目录核倍率（需要联网，只读公开接口）
```

改完 `src/` **必须重新构建**（`lib/` 是产物）；改完 `client/` 也要重跑构建，
然后重启 DSH（宿主在启动时扫描 `dsh.client` 声明）。

### 模型不是全塞进去：**默认一个都不报**

上游实测 85 个模型，全进下拉的话免费那几个会被淹没。所以每个 Agent 有一份上报策略
（设置页里是三个按钮 + 一个带搜索的勾选列表）：`selected`（默认，**不勾不报**）/
`free` / `all`。勾选只是草稿，点「保存并生效」才真正写配置并重发 provider。
详见 [`docs/MODELS.md`](docs/MODELS.md) §6.5。
